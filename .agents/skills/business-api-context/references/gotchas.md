# Measured Gotchas

> Loaded by: `business-api-context`, when reading this project's api map could mislead a competent session. Every row was measured on the date given against the source it names. Rows that stop being true move to §"No longer true"; they are never deleted. Proposed and applied per `agentic-qa-core/references/skill-refinement-protocol.md`.

## 1 · Reading the map

| # | Gotcha | Symptom | Fix | Measured | Verified against |
|---|---|---|---|---|---|
| 1 | `Idempotency-Key` is required, not optional, on the fourteen idempotent creates, among them `POST /workspaces`, `POST /tests`, `POST /runs`, `POST /test-plans/{id}/tests` and billing checkout | 400 `idempotency_key_required` on the first API test that omits it; reusing a key with another body gives 409 | Send a fresh `Idempotency-Key` header (8 to 128 word characters or dashes) on every idempotent create | 2026-11-17 | Handler code at product `origin/staging` 4ccd8ede (read, no live call); api map `error-semantics`, `group-workspace-lifecycle`, `discovery-gaps` |
| 2 | Sign-in, confirm and check-email budgets are counted per network source, read only from `x-vercel-forwarded-for` or `x-real-ip`; without either header every request shares one `unknown` bucket | Parallel workers or one CI runner get 429 `rate_limited` on sign-in | Reuse the PAT from setup and budget logins (ADR-0018); whether staging forwards a distinct source per runner is unverified | 2026-11-17 | Api map `auth-rate-limits`, `discovery-gaps` (product `origin/staging` 4ccd8ede, read, no live call) |
| 3 | A 502 `upstream_error` on sign-in can be the throttle's counter store failing closed, not Supabase | A sign-in failure is triaged as an auth-provider outage | Treat 429 with `Retry-After` as the real throttle and a 502 as the store failing closed; check both before filing | 2026-11-17 | Api map `auth-rate-limits` (product `origin/staging` 4ccd8ede) |
| 4 | Workspace-bound PAT enforcement is partial: only the `workspace:admin` handlers, `GET jira-connection` and `POST /runs/submissions` check the binding; other routes rely on the owner's role | A cross-workspace negative test with a bound token gets 200, not 403 | Confirm live before asserting a 403; the gap is a candidate bug, not settled behaviour | 2026-11-17 | Api map `auth-model`, `discovery-gaps` (unverified live; product `origin/staging` 4ccd8ede) |
| 5 | Re-marking a run step with a different result gives 409 `run_step_conflict` under the PAT, but silently overwrites under the cookie session; an identical re-mark returns 200 | An API test (PAT) and a UI test (cookie) disagree on the same scenario | Assert the behaviour per credential; never reuse one expectation for both | 2026-11-17 | Api map `group-runs` (product `origin/staging` 4ccd8ede) |
| 6 | `POST /runs/submissions` takes `idempotency_key` in the body, not the `Idempotency-Key` header; the same key and payload within 24 hours returns the first Run (200, `replayed: true`), another payload under the key is 409 | A retry test expects a new Run; a header-only key is ignored | Send the key in the body; assert `replayed: true` on retry and 409 on a changed payload | 2026-11-17 | Api map `group-automated-runs` (product `origin/staging` 4ccd8ede) |
| 7 | Five handlers sit outside the contract: `GET /api/openapi`, `OPTIONS /api/v1`, the Stripe webhook, `/auth/callback` and `/auth/oauth/{provider}`; bypass routes use no error envelope | No generated types exist for them in `api/openapi-types.ts`; an envelope assertion fails | Type and assert these by hand; do not look for them in `api:sync` output | 2026-11-17 | Api map `endpoint-groups`, `error-semantics` (product `origin/staging` 4ccd8ede) |
| 8 | Crons are not registered on staging: a manual `POST` with `CRON_SECRET` is the only way to run digest or storage cleanup there | A test waiting for a scheduled run on staging never sees it | Trigger by manual `POST`; whether `CRON_SECRET` is set on staging is unchecked | 2026-11-17 | Api map `auth-system-callers`, `discovery-gaps` (product `origin/staging` 4ccd8ede) |
