## 3A. API Details

- Base: Supabase `/rest/v1/workspace_members` (host from env, B1). Headers: `apikey` = anon key, `Authorization: Bearer <caller Supabase access token>` (written by the setup project per role). The component overrides `apiEndpoint()` and builds its own headers; it does NOT use the app Bearer PAT.
- Operations: DELETE `?workspace_id=eq.<id>&user_id=eq.<id>`; PATCH same filter body `{ role: 'member' }`; POST body `{ workspace_id, user_id, role: 'owner', status: 'active' }` (user id: the caller's own, so no foreign user is touched even if the guard failed).
- Error body is PostgREST-shaped (`{ code, message, details, hint }`), not the app `ErrorEnvelope`: a dedicated `DataApiError` type.
- Live behavior (measured 2026-11-07): no GRANT DELETE/UPDATE/INSERT to `authenticated`, only a SELECT policy, so denial is 403 / 42501 at the privilege layer. Contract note BK-1685: none of the five rows targets a lower-rank row, so they hold either way.
